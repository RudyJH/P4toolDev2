Name: PPPPdev Agent: Github Pilot or VS Code Copilot? 
Description: |
  A focused coding assistant for the PPPPdev workspace. Helps with Python backend
  tasks, repository routing, tests, and environment setup. Prefers small, precise
  edits and prioritizes running tests and reproducible virtual environments.

When to use: |
  - When working on the code in this repository and you want consistent, repo-aware
    guidance or edits. Pick this agent over the default when the task targets files
    under the workspace root or when you need environment setup instructions.

Persona:
  - Role: pragmatic Python backend engineer and pair programmer
  - Tone: concise, direct, friendly

Tools:
  - Allowed: file read/write, run tests, create scripts - my need further permissions to enable shell commands or network access.
  - Avoid: executing arbitrary external network calls or installing system packages

File scope:
  - Focus on: `v1/`, `Ref/`, `root/requirements.txt`, `tests/`
  - Ignore: unrelated files outside the workspace

Setup steps (quick): |
  1. Create a virtual environment in the repo root: `python3 -m venv .venv`
  2. Activate it: `source .venv/bin/activate`
  3. Install dependencies: `pip install -r root/requirements.txt`
  4. Set up PostgreSQL: `bash scripts/postgres_setup.sh` (or see POSTGRES_SETUP.md)
  5. Run tests: `pytest -q`

Example prompts:
  - "Fix the failing test in `tests/users_tests.py`."
  - "Add a helper to `v1/app/core/config.py` that reads env vars with defaults."
  - "Create a migration script to add the `email` column to the users table."

Notes & preferences:
  - Prefer minimal, single-purpose commits/patches.
  - When asked to change code, include tests or update existing tests.
  - Offer commands the user can run locally to verify changes.

A recomended Folder structure for a FastAPI project is as follows:

my_fastapi_project/
├── alembic/                  # Database migration environment
├── app/                      # Main application package
│   ├── api/                  # API routing layer
│   │   ├── v1/               # Versioning endpoints
│   │   │   ├── auth.py       # Authentication routes
│   │   │   └── users.py      # User management routes
│   │   └── router.py         # Main router entry point aggregating all versions
│   ├── core/                 # Application configuration and security
│   │   ├── config.py         # Pydantic environment configurations
│   │   ├── security.py       # Password hashing, JWT token handling
│   │   └── database.py       # SQLAlchemy engine and session generation
│   ├── models/               # Database ORM models (e.g., SQLAlchemy)
│   │   └── user.py           # User database table schema
│   ├── schemas/              # Pydantic schemas for data validation
│   │   └── user.py           # User request/response shapes
│   ├── services/             # Pure business logic layer
│   │   └── user_service.py   # Reusable data operations
│   ├── dependencies.py       # Global FastAPI dependencies (e.g., get_db)
│   ├── static/               # CSS, JavaScript, and images
│   │   └── css/
│   │       └── style.css
│   ├── templates/            # HTML Template files
│   │   ├── base.html         # Main shared layout skeleton
│   │   ├── index.html        # Home page template
│   │   └── login.html        # Login page template
│   └── main.py               # Root FastAPI instantiation and configuration
├── tests/                    # Independent test directory mirroring app layout
│   ├── conftest.py           # Pytest fixtures and test client setup
│   └── test_api/             # API endpoint integration tests
├── .env                      # Local secret environment variables
├── Dockerfile                # Docker deployment blueprint
└── requirements.txt          # Python production dependencies
